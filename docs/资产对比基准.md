# 资产对比基准（1 / 3 / 7 天前）

「资产」面板右上角的对比下拉，用来决定卡片上那个 `↑ / ↓` 变化值是跟**哪一天**比。

## 界面

- 日期下拉：选看哪一天（默认今天）。
- 对比下拉：`对比 1 天前` / `对比 3 天前` / `对比 7 天前`，默认 `1 天前`。
- 基准：显示实际取到的那一天（`基准 10-31`）。取不到基准时显示 `--`，变化值留空。

## 取基准的规则

设选中 N 天前、正在看 D 日：

1. 先看 `D - N` 那天有没有记录，有就直接用。
2. 没有就在 `[D - N, D - 1]` 这个窗口里找**离今天最远**的那一份（也就是最贴近 `D - N` 的一笔）。
3. 窗口里一份都没有 → 不给基准，卡片只显示当前数值，不显示假的变化。

不往窗口外找，是为了避免「对比 7 天前」实际上拿一个月前的数据来比，数字看着对、意义不对。

## 接口

`GET /income/{script}?date=YYYY-MM-DD&compare=N`

- `compare` 省略或 `0`：退回老口径——上一个有记录的日子（不限窗口），保证老客户端不受影响。
- 响应新增 `compare_days`，前端据此回显下拉选项；`baseline_date` 是实际用到的基准日。

后端实现在 OAS 仓库 `module/log_income.py`：

- `find_income_baseline(config_name, before, window_days=None)`
- `build_income_report(config_name, day, compare_days=0)`
- 路由：`module/server/income_router.py`

## 验收

1. 打开「资产」tab，头部应能看到 `日期` + `对比 1 天前` + `基准 MM-DD`。
2. 切到 `对比 7 天前`，基准应跳到 7 天前那天；若那天没记录，落到窗口里离得最远的一份，不会跳出 7 天。
3. 切回 `对比 1 天前`，卡片变化值应立刻按新基准刷新，日期列表不重新拉取。
